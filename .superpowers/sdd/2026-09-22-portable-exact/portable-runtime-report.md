# Portable runtime foundation

Implemented ABI 2 with shell-semantic profile `bash53-i64` independent of native target. The description is exactly a header, capability line and `target TARGET` line. Native targets are x86_64-linux, aarch64-linux and aarch64-darwin. Captured runtime compatibility checks compare ABI, profile, required capabilities and the executing host target; new providers reject ABI 1. Old immutable generations and captured providers are untouched.

Child transport no longer enumerates `/proc` or reopens `/dev/fd` paths. A mode-0700 owned temporary directory contains mode-0600 generated Fish script and scalar-state files. Fish independently opens their offsets at zero. Paths use native filesystem encoding, avoiding `Char8` corruption. Parent waits before deterministic cleanup; owner TERM/INT/QUIT/HUP/PIPE exceptions clean resources and reap its direct child. The four input frames and raw output protocol remain unchanged. Transport payload is not a Bash interpreter or user process-substitution data file.

The native descriptor layer records initial descriptors before RTS initialization, uses platform F_DUPFD_CLOEXEC constants, and prevents arbitrary inherited/RTS descriptors escaping exec. Linux uses optional close_range(CLOEXEC) with POSIX fallback. Darwin uses its libproc descriptor inventory (Apple system API, no filesystem dependency), including descriptors above a subsequently lowered soft limit. Capture pipe Handles have one closing owner to avoid closing reused descriptor numbers. Child exec resets shell signal dispositions. Native exports include NativeTarget constants plus Descriptors duplicatePrivate/privateCloseOnExec for subsequent session integration.

## Native session/jobs and canonical update

The ABI2 session owner now launches the private generated Fish evaluator, authenticates a Unix socket with a random per-session token, and receives user stdio by SCM_RIGHTS. `session-client --reply` snapshots cwd/environment and writes only to a private reply file; the generated caller invokes it outside command substitution because Fish drops inherited fd3/4/5 in command substitutions. External child environments omit private session markers. Run/spawn requests return actual native user/last-pipeline-stage PIDs, native owners represent compiled body regions, and evaluator PIDs never enter job records. The owner caches all pipeline member statuses, implements pipefail, retains explicit wait statuses, consumes records for wait-with-no-operands, and emits Bash diagnostics for unknown/empty/out-of-range PIDs. Background inherited stdin is /dev/null. Parent normal completion leaves asynchronous children running. Snapshot script/state transport is frame-based and does not hit exec argument limits.

Capsules support exec launch even from Fish -c/stdin: session-prepare streams arbitrary compiled evaluator bytes into a private capsule and returns its path/token. A separate execed guardian inherits only its owned socket. Authenticated takeover transfers a close-on-exec lifetime lease to the native owner; lease EOF triggers capsule cleanup. Startup waiting has a 60-second timeout before source effects; running programs have no lease timeout. Nested child-run-session/child-capture-session launch new native owners.

Two additional concrete regressions drove fixes: a guardian holding inherited fd200 delayed source-pipe EOF, fixed by an exec boundary with explicit listener inheritance; fork-only builtin writers retained CLOEXEC pipe readers and hung instead of SIGPIPE, fixed by an execed native byte writer whose staged input is unlinked before output. This preserves actual signal termination and avoids signal-time file leaks.

## Descriptor scopes, byte reads and signal completion

The source descriptor table owns duplicate references to shared open-file descriptions. Ordered open/append/read-write, dup, close and byte-data operations preserve offsets and scope restoration. Here-data lives in an unlinked private file with an independently opened read position; it does not synchronize process-substitution data. Child installation first protects sources above all target numbers, preventing dup cycles/reuse from clobbering descriptors. A nested snapshot receives its virtual descriptor manifest, copies owned references, and does not expose those source descriptor numbers to its private Fish evaluator. Nested command capture is requested from the existing owner before stdout replacement, so scoped fd3 aliases retain shared parent offsets. Failed-open diagnostics use the effective virtual stderr.

`read` processes one byte at a time without read-ahead. It supports raw mode, literal delimiter including NUL, bounded byte count, explicit source fd, scalars including the final-variable remainder, REPLY and dense arrays. Its private response includes an assignment flag: invalid descriptors preserve bindings, while EOF assigns the partial/empty result. Canonical read.py compares raw bytes, NUL skipping, delimiters, EOF, IFS whitespace/nonwhitespace, escapes, counts and arrays against Bash5.3.9. descriptors.py passes scope/alias offsets, invalid-read flag, virtual-stderr open errors, and nested native command-capture fd3 sharing. Session tests verify closed stdout yields source-aware status1 write diagnostics. `finish-signal 13` defers native SIGPIPE until evaluator EXIT handling and owned resource cleanup; a native parent observes signal -13 even if the evaluator exits9.

## Owned process-substitution pipes

The rejected FIFO design had a concrete race: a producer could finish before the consumer opened the FIFO pathname, leaving that open blocked despite an inherited reader. The implemented endpoint is instead a real pipe with one source-visible inherited descriptor path, `/dev/fd/N`. This uses pipe alias semantics only, including Darwin's shared description behavior; it does not reintroduce independent-offset assumptions or procfs enumeration. `PipeDescriptorPaths` is an explicit capability, and `pipe-paths` performs a real pipe alias roundtrip plus EOF probe before source effects. Linux endpoint execution is still unverified locally.

The owner launches input/output substitutions as actual external children or compiled region owners and caches the PID as a job. It keeps the consuming end in a short-lived lease, excludes that end from the producer, transfers leases into the next owned invocation, then closes the owner's references immediately. The consumer's process lifetime owns the inherited endpoint. `fd-endpoint` instead transfers a lease into an ordered virtual redirection scope, enabling native read and builtin redirects. Explicit release closes unused pending leases; normal owner completion does not wait for asynchronous producers. There are no producer data files or synchronizing temporary-file shortcuts.

Canonical process-substitution.py passes input/output bytes, a producer completely finished before pathname opening, actual PID wait, a 300KB writer with an early-closing reader (SIGPIPE141), and an endpoint redirected into scoped stdin consumed by native read. Final focused canonical passes additionally include portable.py, protocol.py, printf.py, read.py, descriptors.py, session.py, and test/native/child-transport.sh. `hlint runtime-src runtime-app` reports no hints. Full integrated and property evidence remains coordinated with the controller.

The wait-all process-substitution rule has separate job metadata: only the latest substitution still represented by the last asynchronous PID participates in implicit wait, alongside ordinary background jobs. A subsequent background launch supersedes it. Older substitutions remain explicitly waitable. A no-sleep FIFO handshake regression first demonstrated the owner incorrectly blocking on the older producer and deleting its cached status; the fix selects and consumes only implicit-wait records.
